# 中文分词

znlp 的分词是**词图 + 固定阶段**，不是单一算法。候选词先铺进有向无环图，选路只选一种策略，然后用约束强制成词，最后标注。对外组装是 `SegmentRecipe`，不是插件总线。

源码根包：`dev.znlp.segment`。配方在 `segment.recipe`。感知机训练/解码在 `dev.znlp.perceptron`，分词模块只消费模型。

## 默认能做什么

`Znlp.segmenter()` 等于 `SegmentRecipe.standard().build()`：

| 阶段 | 内容 |
| :--- | :--- |
| 铺候选 | 核心词典 DAT 全匹配、短人名、原子识别（数字/时间/英文等，不覆盖已有词典顶点） |
| 选路 | 二元 Viterbi |
| 强制成词 | 三字以上人名 |
| 标注 | 感知机词性（北大词性集 `Nature`） |

示例句 `南京市长江大桥` 的默认结果是 `[南京市, 长江, 大桥]`：词典里没有「长江大桥」，二元表也几乎没有这几个词的共现，Viterbi 按一元词频选出这条路。这不是最长匹配，也不是感知机分词。

CWS、NER、规则、用户词典、纠错**不进默认流水线**，用 Builder 按需安装。

## 调用入口

```java
List<Token> tokens = Znlp.segment("自然语言处理技术是人工智能的重要领域");
List<String> words = Znlp.segmentToStrings("南京市长江大桥");
WordSegmenter shared = Znlp.segmenter(); // 惰性单例，可多线程复用
```

换组合时用配方。词典和模型仍由 `ServiceLocator` 提供，调用方不按 Class 去取算法：

```java
WordSegmenter cws = SegmentRecipe.perceptron().build();

WordSegmenter ner = SegmentRecipe.standard()
        .withNer() // 会带上词性
        .build();

WordSegmenter custom = SegmentRecipe.dictionary()
        .withUserDictionary(dict)
        .withRules(ruleManager)
        .build();
```

`WordSegmenter` 无状态。核心方法是 `segment(char[], Consumer<Token>)`；`segment(String)` 会一次装进 List，长文本用回调。

流式读、停用词/标点过滤走 `WordSegmentReader`，它包在分词器外面，不改切分。

## 流水线

```
char[]
  │
  ▼
CharNormalize[]                 可选；复制后再改，不改调用方数组
  │
  ▼
按 。！？； 和换行切句           offset 加回原文
  │
  ▼
Wordnet                         空图 + Begin / End
  │  CandidateSource.fill       配方顺序铺候选
  │  wordnet.fillNill()         空洞补 length=1、freq=1
  ▼
BestPathAlgorithm.select        恰好一种：Viterbi 或线性路径
  │
  ▼
SpanConstraint                  优先级从高到低：纠错、用户词典、长人名
  │
  ▼
TokenAnnotator                  词性，然后 NER（允许合并）
  │
  ▼
WordTermCollector               普通 Token，或索引子词
  ▼
Consumer<Token>
```

关掉某项能力就是配方里不放它。没有 `disable()`，也没有整数 `order`。

## 词图

句子表示成按字符下标分行的 DAG。每行一个 `VertexRow`，行内顶点按**长度升序**链表存放，同长度唯一（后 `put` 替换先到的）。

```
#S# [-1]  南 [0] {南, 南京, 南京市}  京 [1] {京}  市 [2] {市, 市长}  …
          长 [3] {长, 长江}          江 [4] {江, 江大桥?}  大 [5] {大, 大桥}  桥 [6] {桥}  #E#
```

智能下标：`-1` 是 Begin，`0 … n-1` 是原文位置，`n` 是 End。`Vertex` 不存字符串，用 `(offset, length)` 指回 `char[]`。

| 类 | 职责 |
| :--- | :--- |
| `Wordnet` | 图：行数组、Begin/End、`fillNill`、`subWordnet`、上下文 Map |
| `VertexRow` | 某一字符位置上所有可能词 |
| `Vertex` | 一个候选：`length`、`wordID`、`freq`、`nature`；Viterbi 用的 `from`/`weight` |
| `Wordpath` | 切分方案：`BitSet[i]=true` 表示第 i 个字符后切开 |
| `VertexHelper` | 创建 Begin（`Nature.begin`）/ End（`Nature.end`） |

后处理改切分靠 `Wordpath.combine(from, length)`：改 BitSet，必要时在图里补顶点。`willCutOtherWords` 只看合并跨度的左右是不是已有切分点，**不看内部**——允许把 `南京/市` 合成 `南京市`，不允许切开已经选定的邻词。

`subWordnet` 只复制长度，不复制 `wordID`/`freq`/`nature`。子图上再跑 Viterbi 几乎只剩平滑项，智能子词切分依赖回原图查词典。

## 配方怎么装阶段

`SegmentRecipe.build()` 按字段生成阶段名单，不经过插件接口。

| 配方 | 铺候选 | 选路 | 强制成词 | 标注 |
| :--- | :--- | :--- | :--- | :--- |
| `dictionary()` | 核心词典、规则、额外候选、原子 | Viterbi | 用户词典、纠错 | 无 |
| `standard()` | 上面再加短人名 | Viterbi | 再加长人名 | 词性 |
| `perceptron()` | CWS 边界、规则、额外候选、原子补洞 | 线性路径 | 用户词典、纠错 | 按 `withPos` / `withNer` |

`withNer()` 会打开词性。用户词典和纠错的优先级是纠错高于用户词典，用户词典高于长人名。同跨度上，原子识别使用 `FILL_IF_ABSENT`：已有词典顶点只补空词性，不替换 `wordID` 和词频。

`SegmentModule`（priority 50）注册词典、二元表、原子算法和各感知机工厂。配方在 `build()` 时取出这些单例，自己 new 出无状态的算法对象。

扩展只实现三个接口之一，再 `addCandidate` / `addConstraint` / `addAnnotator`：

| 接口 | 允许做的事 |
| :--- | :--- |
| `CandidateSource` | 往词图放跨度，并声明同跨度冲突策略 |
| `SpanConstraint` | 在已选路径上按优先级强制合并 |
| `TokenAnnotator` | 给稳定边界打标签；只有 `mayMerge()` 为真才能改边界 |

## 默认路径细节

### 核心词典

`CoreDictionarySplitAlgorithm` 用 DAT 一次扫完全句，每个命中生成带 `wordID` 和词频的顶点。`wordID` 与二元表同一套 ID。

资源：`znlp/core-dict/CoreDict.txt`（词 + 空格 + 频次）。首次加载编成 DAT 写到 `cache-dir`，前缀 `CoreDict_`。词表约 22 万条，**不含词性**；词性由 POS 后处理补。

词典加载时会插入 10 个抽象词标签（见下），保证 Begin/End、数词、人名等有稳定的 `wordID` 0–9。

### 原子识别

`AtomSplitAlgorithm` 先看句子里有没有数字或字母，没有就跳过。有则把阿拉伯数字/`N`、字母/`A`、中文数字/`Z` 归一后，用模板 DAT 匹配时间、数词、数量词、英文等，再扫邮箱和 `iphone7` 这类混排。

配方里原子识别用 `FILL_IF_ABSENT`：同跨度已有顶点时只在词性为空时补词性，不改 `wordID` 和词频。没有顶点时才 `put` 并 `setAbsWordNatureAndFreq`。

模板在 `DefaultTemplate`，语法由 `AtomTemplateParser` 展开（`{N[1,2]}`、`{(日|号)}`）。

### 人名

感知机模型：`znlp/personname/nr-name.model`。

- **图阶段**（`PersonNameAlgorithm`，`length ≤ 3`）：当该跨度还没有顶点、且**不会切开更早位置长度 ≥ 2 的已有词**时，插入 `Nature.nr`、默认频次 10000。用来避免「陈宝奇怪…」被拆开，也避免「江大桥」切开「长江」。
- **路径阶段**（`PersonNameProcessor`，`length > 3`）：`willCutOtherWords` 为假才 `combine`。已有 `nr` 顶点直接跳过，不再强制并进当前路径。

识别结果放在词图上下文键 `PersonNameAlgorithm.CONTEXT_KEY`，强制成词阶段复用，不跑第二次。三字及以内只进词图；更长的人名在选路之后按优先级合并。

### 词性

`PosPerceptronProcessor` 在路径定稿后，对词序列做感知机标注。模型：`znlp/pos-model/pos.model`。

覆盖规则：顶点还没有词性，或词性是 `newWord` / `nr` 时，用模型结果；词典/原子已经写下的其它词性保留。模型标成 `nr` 且原词性为空、长度 > 3 时降为 `n`，用来压「基础设施/nr」这类误标。

默认分词器已装词性。单字也走词图，不再在长度为 1 时直接标成 `x` / `w`。

## Viterbi 选路

`ViterbiBestPathAlgorithm` 沿用 HanLP：边权**越小越好**。从 Begin 推到 End，再沿 `from` 指针回溯，对每个顶点 `Wordpath.combine`。

无共现时退回一元平滑；`freq==0` 当成 1，避免除零。`wordID < 0` 的自定义词二元贡献为 0，**不会**被强制选中（相关逻辑已注释掉）。用户词要进最终切分，靠后处理 `combine`。

共现表：`znlp/core-dict/CoreDict.bigram.txt`，CSR 稀疏矩阵，缓存前缀 `BiGramTable_v2_`。句首抽象词键是 `\u00010Begin`，加载时只剥行尾空白，不能 `String.trim()`（会削掉 `\u0001`，整段句首二元丢失）。

很多常见搭配在表里频次为 0（例如 `南京市→长江`、`长江→大桥`）。没有二元时观感上像「只用了词典」。

回溯走不到 Begin 会抛 `IllegalStateException`（「非完整路径」）。`fillNill` 的职责就是堵住这种洞。

## 抽象词

核心词典和二元表共用 10 个以 `\u0001` 开头的标签，DAT 排序靠前，ID 固定 0–9。`DictionaryAbsWords.nature2id` 把 `Nature` 映到这些 ID；不在表里的词性（包括 `newWord`）返回 -1，`setAbsWordNatureAndFreq` 不会写入 `nature`/`freq`。

| ID | 标签 | Nature |
| -: | :--- | :--- |
| 0 | `\u00010Begin` | `begin` |
| 1 | `\u00011End` | `end` |
| 2 | `\u00012MQ` | `mq` |
| 3 | `\u00013NX` | `nx` |
| 4 | `\u00014Time` | `t` |
| 5 | `\u00015String` | `x` |
| 6 | `\u00016NT团体` | `nt` |
| 7 | `\u00017NS地名` | `ns` |
| 8 | `\u00018NR人名` | `nr` |
| 9 | `\u00019Num` | `m` |

人名、原子数词、时间都走这条通道，才能和「0Begin → 人名」这类二元接上。`Nature.newWord` 不在这张表里，感知机未登录词直接写 `nature` 和词频，不走 `setAbsWordNatureAndFreq`。

## 可选配方

### 感知机分词（CWS）

`SegmentRecipe.perceptron()` = `CwsSplitAlgorithm` + 原子补洞 + `LinearPathAlgorithm`。模型目录 `znlp/cws-model/`，字级 BMES（B/M/E/S），遇 E 或 S 切一刀。

词典已有的词带上 `wordID`/词频；未登录词直接写成 `Nature.newWord`、词频 1。切分边界写入词图上下文 `CwsSplitAlgorithm.SPANS`，线性路径按这份边界成词。原子识别只合并仍然是单字的空洞，不跟感知机边界竞争。也可以绕过词图：`CwsPerceptron.split`。

感知机配方和词典配方是两套选路，不要叠在同一次 `build()` 里。

### NER

`SegmentRecipe.withNer()` 先装词性，再装 `NerProcessor`。NER 在已切好的词序列上做 BIO，合并 `B-/M-/E-` 的 ns/nt，并声明 `mayMerge()`。模型：`znlp/ner/ner.model`。

当前实现把标签 `"S"` 和 `"O"` 同等丢弃，**单字实体 `S-ns` / `S-nt` 不会改词性、不会合并**。异常只打日志，不中断分词。

### 规则

`SegmentRecipe.withRules` 把 `RuleBasedWordSplitAlgorithm` 放进铺候选。命中后把 `freq` 抬到 `1000000 + priority`，已有顶点则保留 `wordID`。这套高词频只对 Viterbi 配方有选择力。预制规则在 `CommonRules`：URL、邮箱、手机、身份证、IPv4。`RuleSegmenterPluginBuilder` 负责把规则收成 `RuleManager`。

整句会 `new String(char[])` 再跑正则。规则词若 `wordID == -1`，二元为 0，全靠超高词频。

### 用户词典

`withUserDictionary` 在选路之后强制合并。跨度不能从别的词中间切开，但已经在词图里的用户词也会拉回路径。更高优先级的约束（纠错）不会被它覆盖。

词典来源：`MemUserDictionary`、`FileUserDictionary`、`ResourceUserDictionary`（`ResourceDictKind`：通用、人名、地名、机构等）。`UserDictionaryPluginBuilder.dictionaries()` 把多个词典收成列表。

### 纠错

`withCorrections(dict)` 把 `CorrectionWordpathProcessor` 放进强制成词，优先级高于用户词典。默认资源路径 `correction-dict/correction_dict.txt` 仓库中不存在，调用方自备 `CorrectionDictionary`。

## 结果收集

| 收集器 | 行为 |
| :--- | :--- |
| `SimpleWordTermCollector` | 默认。路径上每个顶点 → 一个 `Token`（词、词性、offset） |
| `SentenceCollector` | 可挂子词策略；会丢掉纯空白 Token |

子词（搜素索引等场景）在收集阶段算，不改主路径：

- `IndexSubwordComputer`：词图里所有长度 ≥ 2 的子串
- `SmartSubwordComputer`：对 `length>2` 建 `subWordnet` 再 Viterbi；人名不拆
- `RuleDictSubwordComputer`：规则表（`A/BC`、`A?C`）

`Token.subword` 挂子词；主列表仍是粗切。

## 如何加一种能力

**只改切分候选**（数字、URL、领域词进图）：实现 `CandidateSource`，或沿用 `WordSplitAlgorithm` 再用 `SplitCandidate` 包上冲突策略。`addCandidate` 加到配方末尾、原子识别之前。

**只强制成词**（用户词、纠错）：实现 `SpanConstraint`，在 `apply` 里调用 `Wordpath.canForce` / `force`。优先级用 `StagePriority` 旁边的数字，大的先执行。

**只打标签**：实现 `TokenAnnotator`。要合并边界就让 `mayMerge()` 返回 true，并在 `annotate` 里 `combine`。

```java
WordSegmenter segmenter = SegmentRecipe.standard()
        .addConstraint(new AcmeConstraint(dict))
        .build();
```

需要系统注入的词典和模型在 `SegmentModule.register` 登记工厂或单例。配方 `build()` 时再取。

## 如何改一处行为

- 默认不要词性 / 人名：用 `SegmentRecipe.dictionary()`。
- 领域词必须切出来：`withUserDictionary`。它在选路之后强制合并，不必再把词频抬到百万。
- 感知机切分：`SegmentRecipe.perceptron()`。选路是线性路径，不和二元 Viterbi 混用。
- 原子识别保留词典顶点：配方里原子使用 `FILL_IF_ABSENT`。
- 演示句要切成 `南京市/长江大桥`：补核心词「长江大桥」和/或二元 `长江→大桥`，或把「长江大桥」放进用户词典。
- 测性能：独立模块 JMH，见 [基准.md](基准.md)，不要放进 `:znlp:test`。

已知缺口与模块对照见 [分词模块审查.md](../分词模块审查.md)。本文描述的是当前设计，审查表里「未修」项仍按源码行为理解。
