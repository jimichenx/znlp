# 分词性能基准

独立模块 `znlp-benchmarks`，用 JMH 测分词热路径。**不进入** `./gradlew :znlp:test`。

## 跑法

```bash
# 默认：短/中/长句 × 默认流水线 / 仅二元 / CWS 流水线 / CWS split
./gradlew :znlp-benchmarks:jmh

# 只跑某一方法（末尾 `$` 避免 JMH 正则匹配到 defaultSegmentToStrings 等）
./gradlew :znlp-benchmarks:jmh -PjmhArgs='SegmentBenchmark.defaultSegment$'

# 正式对比（多 fork）
./gradlew :znlp-benchmarks:jmh -PjmhArgs='SegmentBenchmark -f 2 -wi 5 -i 10'
```

JSON 结果写到 `znlp-benchmarks/build/results/jmh.json`，不提交。优化前后在同一台机器、相近负载下对比；不要把数字当 PR 硬门禁。

词图热路径优化对照这两条，并打开 GC profiler，同时看平均时间和分配速率（`gc.alloc.rate.norm`，单位 B/op）：

```bash
# 优化前：跑完后把 jmh.json 复制为 jmh-baseline.json，避免下一轮覆盖
./gradlew :znlp-benchmarks:jmh -PjmhArgs='SegmentBenchmark.(defaultSegment|bigramOnlySegment)$ -prof gc'
cp znlp-benchmarks/build/results/jmh.json znlp-benchmarks/build/results/jmh-baseline.json

# 优化后
./gradlew :znlp-benchmarks:jmh -PjmhArgs='SegmentBenchmark.(defaultSegment|bigramOnlySegment)$ -prof gc'
```

`defaultSegment` 含人名和词性。`bigramOnlySegment` 只有词典、原子和 Viterbi，用来看词图本身。正确性不看这里，看 `SegmentSnapshotTest` 的词、词性和 offset。

## 测什么

| 基准 | 对应路径 |
| :--- | :--- |
| `defaultSegment` | `Znlp.segmenter()`：词典 + 二元 + 人名 + POS |
| `bigramOnlySegment` | `SegmentRecipe.dictionary()`，不含人名和词性 |
| `cwsPipelineSegment` | `SegmentRecipe.perceptron()`，线性路径 |
| `cwsPerceptronSplit` | `CwsPerceptron.split`，不走词图 |
| `defaultSegmentToStrings` / `defaultSegmentConsumer` | 收集方式开销 |

语料内置三档：`short`（南京市长江大桥）、`typical`、`long`（约 200 字），不读外部大文件。

## 和单测的关系

- 正确性：`znlp/src/test`，JUnit。
- 性能：本模块，JMH。旧的 `*Benchmark` JUnit 类仍可用 `-PincludeTags=benchmark` 跑，新的分词优化请只看 JMH。
